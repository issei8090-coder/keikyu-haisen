# 前面展望速度プロファイル：実装引き継ぎ（Claude Code向け）

## 目的

`front_view_profile_keikyu_up.json` を使い、動画で観測した京急上り快特1運転分の速度変化を、既存マップ上で「参考走行曲線」として可視化・比較できるようにする。今回の観測は速度制限や信号現示の公式根拠ではない。

## 既存実装を確認した結果

- `index.html` の `VLINES` / `ttVLim()` は、停車駅間の速度上限を遅延回復走行へ適用する運転制御経路。
- このJSONの観測速度を `VLINES` や `ttVLim()` に追加すると、実際の設備上限と、先行列車・信号・運転操作の影響を含む単一走行の実速度が混同される。
- `index.html` は巨大な統合HTMLで、プロジェクト監査メモでは生成物として扱われている。今回は `index.html`、`build/src/*`、配線・進路制御を変更しない。
- 作業フォルダーはGit管理外のため、コア制御へ接続する変更は、Claude Code側で変更前バックアップと生成元確認を行ってから別作業として扱う。

## 今回作る可視化

- JSONを「参照プロファイル」として読み、動画時刻に対する速度の点列を折れ線表示する。
- 駅通過・停車はイベントマーカーにする。`positionKm` がある駅通過点は駅位置へ固定できる。
- `positionKmRange` は駅間の帯として表示し、駅間の細かな位置は補間しない。サンプル時刻から距離を積分して位置を捏造しない。
- `confidence=low` と `speedKmh=null` は補間・平均・学習値へ含めず、注記だけ表示する。
- 信号候補は「現示候補・担当線不明」のマーカーに留める。色だけで実信号の状態を設定しない。
- シミュレーションとの比較は読み取り専用の診断表示にする。まずは速度差を数値・グラフで示し、制御目標に自動反映しない。
- 表示ラベルは「観測実速度（参考・単一運転）」とし、「制限速度」「ATS照査速度」と表記しない。

## 採用しない値・挙動

- 速度値から設備制限、速度標位置、信号位置、信号現示を逆算して確定しない。
- 動画時刻をシミュレーション時刻や時刻表時刻に置き換えない。
- 先行列車が見えるサンプルがあっても、減速原因を先行列車と決めつけない。
- `VLINES` / `ttVLim()`、ブレーキ計算、列車位置、停止目標、進路制御をこの可視化のために変更しない。

## データ・根拠

- 生の目視記録：`build/front_view_observation_working.md`
- 機械可読の観測点・駅間レンジ・平均差分：`build/front_view_profile_keikyu_up.json`
- 駅距離アンカーは `index.html` 内の `KQ_KM`（泉岳寺起点）を転記。駅間内の絶対位置は未知。
- 平均加速度・距離は隣接観測点間の概算のみ。車両の定格加速度・減速度を示すものではない。

## 将来、運転制御へ使う前提

信号・先行列車・進路の状態を同じ時刻・同じ列車・同じ位置で特定した別の観測を複数運転分集める。設備制限の根拠資料と走行速度の観測を別データ系列にし、十分な裏付けができるまでは運転制御の入力にしない。
